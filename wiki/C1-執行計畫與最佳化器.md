# C1 — 執行計畫與最佳化器

**來源**：S2, S11
**適用範圍**：PostgreSQL 18、SQLite

## 最佳化器在做什麼

- PostgreSQL 為收到的每個查詢設計一個**查詢計畫（query plan）**，並選擇預估成本最低者。`EXPLAIN` 顯示該計畫而不執行查詢。[S2]
- SQLite：給定單一 SQL 陳述式，可能有數十、數百甚至數千種實作方式。規劃器的任務是選出磁碟 I/O 與 CPU 開銷最小的那一個。它是成本基礎的，估算各競爭計畫的成本並選預期最快者。[S11]
- 當有多個索引是候選時，SQLite「估算使用每個選項完成查詢所需的總工作量」，選工作量估計最小者。[S11]

## 計畫的結構

計畫是一棵**計畫節點（plan node）樹**：[S2]
- **掃描節點（scan node）**位於底部，從表（或 `VALUES`、FROM 中的集合回傳函數等非表來源）回傳原始列。
- **上層節點**對這些列執行連接、聚合、排序等工作。
- 輸出每個節點一行，以縮排表示樹狀結構。
- **第一行**（最上層節點）給出整個計畫的預估總成本，這就是規劃器試圖最小化的數字。

## 成本數字怎麼讀

每個節點行的形式為 `(cost=startup..total rows=N width=W)`：[S2]

| 欄位 | 意義 |
|---|---|
| **startup cost** | 該節點能開始輸出之前的時間，例如 `Sort` 節點的排序時間 |
| **total cost** | 該節點執行到完成的預估成本。父節點可能提早停止讀取，例如在 `LIMIT` 之下 |
| **rows** | 該節點**輸出**的預估列數，不是它掃描的列數 |
| **width** | 預估的平均列寬，單位為位元組 |

- **單位**：成本是由規劃器成本參數設定的任意單位。慣例上 `seq_page_cost = 1.0`（一次循序磁碟頁讀取），其他參數相對於它。[S2]
- **累計**：上層節點的成本**包含**其子節點的成本。[S2]
- **不計入**：成本忽略傳送給用戶端與值轉文字的開銷，因為規劃器無法改變它們。[S2]

## SQLite 的規劃細節

- 連接順序以「多項式時間的圖演算法」決定（詳見 Next Generation Query Planner 文件），因此 50 或 60 路的連接也能在微秒內規劃完成。[S11]
- `ANALYZE` 提供統計資訊（`sqlite_stat*` 表）。沒有統計時 SQLite 用猜測值，例如：最左索引值平均 10 筆重複、自動索引計價時 N = 一百萬列。文件建議用 `PRAGMA optimize` 保持統計最新。[S11]
