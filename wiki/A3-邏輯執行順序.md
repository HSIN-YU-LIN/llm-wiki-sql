# A3 — 查詢的邏輯執行順序

**來源**：S7, S6
**適用範圍**：PostgreSQL 18 文件明列；概念為 SQL 標準通用

## 內容

PostgreSQL SELECT 文件明列的邏輯求值順序（步驟 1–10）：[S7]

1. `WITH` 子查詢先計算，作為暫時表供 `FROM` 參照
2. `FROM` 清單計算，多個項目互相 cross join
3. `WHERE` 移除不符合條件的列
4. 若有 `GROUP BY` 或聚合函數，進行分組並計算聚合；接著 `HAVING` 移除不符合的**組**
5. 由 `SELECT` 輸出運算式計算出輸出列
6. `DISTINCT` / `DISTINCT ON` 移除重複列（預設 `ALL` 保留）
7. `UNION` / `INTERSECT` / `EXCEPT` 合併多個 SELECT 的結果
8. `ORDER BY` 排序
9. `LIMIT`（或 `FETCH FIRST`）與 `OFFSET` 取子集
10. 鎖定子句（`FOR UPDATE` 等）鎖住選出的列

Table Expressions 文件將前半段描述為一條管線：`FROM` 建虛擬表 → `WHERE` 逐列過濾（條件為 false 或 NULL 的列被丟棄，發生在分組之前）→ `GROUP BY` 分組並計算聚合 → `HAVING` 過濾組。[S6]

## 別名可用範圍（**經原始文件修正過的重點**）

- 輸出欄位別名**可以**用在 `ORDER BY` 與 `GROUP BY`。`GROUP BY` 可用名稱或序號參照輸出欄位；名稱有歧義時，`GROUP BY` 視之為輸入欄位。[S7]
- 輸出欄位別名**不能**用在 `WHERE` 與 `HAVING`，必須完整寫出運算式。[S7]
- 文件未明述理由，但由步驟順序可推：`WHERE`（步驟 3）與 `HAVING`（步驟 4）都早於輸出運算式的計算（步驟 5）。[S7]

> ⚠ 寫稿注意：不可寫成「別名不能用在 WHERE 和 GROUP BY」。GROUP BY 是可以的。
