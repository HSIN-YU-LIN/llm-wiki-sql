# A2 — 宣告式語言與查詢最佳化

**來源**：S11, S2
**適用範圍**：通用

## 內容

- SQL 最重要的特性是它是**宣告式（declarative）語言**而非程序式語言：使用者描述要什麼結果，不描述如何取得。[S11]
- 因此，同一個 SQL 陳述式可能有數十、數百甚至數千種實作方式，取決於查詢複雜度與資料庫結構。[S11]
- 從中挑一個的元件叫**查詢規劃器 / 最佳化器（query planner / optimizer）**。它的任務是選出能以**最少磁碟 I/O 與 CPU 開銷**完成查詢的演算法。[S11]
- PostgreSQL 的做法是對每個查詢建出查詢計畫，並選擇**預估成本最低**的那一個。[S2]
- SQLite 採**成本基礎（cost-based）**：估算各競爭計畫的 CPU 與磁碟 I/O 成本，選預期最快者。[S11]

## 教學重點

「你寫的 SQL 決定要什麼，不決定多快」——整個效能主題的出發點。
從演算法角度看，最佳化器是在**等價查詢計畫的空間中做搜尋**，目標函數是預估成本。
