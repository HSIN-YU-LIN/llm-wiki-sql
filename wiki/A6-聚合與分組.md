# A6 — 聚合與分組

**來源**：S6, S7, S15
**適用範圍**：PostgreSQL 18 文件

## 分組與過濾

- `GROUP BY` 把通過 `WHERE` 的列分組，聚合函數在每一組上計算。[S6]
- `HAVING` 過濾**組**，一如 `WHERE` 過濾**列**。`HAVING` 可以參照分組運算式與聚合結果。[S6]
- 含聚合呼叫、或有 `HAVING` 而無 `GROUP BY` 的查詢，整個被視為**一組**，回傳一列（若被 HAVING 濾掉則零列）。[S6]
- 視窗函數在分組、聚合與 `HAVING` 之後求值。[S6]

## count(*) 與 count(expression) 的差異

- **`count(*)` 計算輸入列數，不論任何欄位值是否為 null。**[S15]
- **`count(expression)` 只計算該引數不為 null 的輸入列。**[S15]
- 兩者都回傳 `bigint`。[S15]
- 文件另註：對整張表做 `count(*)` 是昂貴的，PostgreSQL 必須掃描整張表，或掃描一個涵蓋其所有列的索引。[S15]

## 聚合函數如何處理 NULL

- **多數通用聚合函數忽略 null**，其說明都寫明對「非 null 的輸入值」運算。這涵蓋 `any_value`、`avg`、`bit_and`、`bit_or`、`bit_xor`、`bool_and`、`bool_or`、`every`、`max`、`min`、`range_agg`、`string_agg`、`sum`、`xmlagg`。[S15]
- **部分聚合函數包含 null**：`array_agg`（非陣列輸入時）會收集 null，`json_agg` 也包含；`json_agg_strict` 與 `jsonb_agg_strict` 則跳過。[S15]
- **假設集聚合**（`rank`、`dense_rank`、`percent_rank`、`cume_dist`）明確不是 strict 的，不會丟棄含 null 的列。[S15]
- **統計類聚合**使用 *N* = 所有輸入運算式皆非 null 的列數；計算無意義時（例如 *N* 為 0）回傳 null。[S15]

## 沒有任何列時回傳什麼

- **除了 `count` 以外，這些函數在沒有選出任何列時回傳 null。**[S15]
- 文件特別指出 `array_agg` 回傳 null 而非空陣列。需要以 0 或空陣列代替時應使用 `coalesce`。[S15]
- `sum`、`avg`、`max`、`min` 在無輸入列時皆回傳 null。[S15]

> ⚠ 寫稿注意：文件**未明述**「所有輸入皆為 null」時的結果。由「忽略 null」可推論應為 null，但這是推論而非文件陳述，簡報中不可寫成文件的說法。
