# B6 — 索引的代價

**來源**：S9, S12, S4
**適用範圍**：通用

## 三項成本

MySQL 文件列出三點：[S9]
- **浪費空間**：每個索引都佔儲存空間，即使沒有任何查詢用到它。
- **浪費最佳化器時間**：MySQL 必須評估可用的索引來決定用哪一個，多餘的索引增加規劃開銷。
- **拖慢寫入**：insert、update、delete 都必須同時更新受影響表上的**每一個**索引。

Use The Index, Luke 的對應說法：資料庫在每次 insert、update、delete 時自動維護 B-tree，這為寫入操作增加負擔。[S12]

## 結論

- 必須在這些成本與查詢速度之間取得平衡。在 `WHERE` 子句用到的欄位上建索引能加快 `SELECT`，但**為每一個可能的欄位都建索引會適得其反**。目標是最佳的索引集合：足以讓重要查詢變快，而不必為效益低又拖慢寫入的索引付出代價。[S9]
- MySQL 文件**未量化**這些成本，也未給出選擇索引的規則。[S9]
- 覆蓋索引的 payload 欄位會重複表中資料、使索引變大，可能拖慢搜尋。[S4]

> ⚠ 寫稿注意：不可寫出「索引會讓寫入慢 N 倍」這類具體數字，來源未提供任何量化。
